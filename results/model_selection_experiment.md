# 공 추적·모델 선택 실험 기록 (2026-11)

## 요약
- 공 추적기 구현(학습 없음, 검출 후보를 동적 계획법으로 연결) 후 평가: 검출이 약하면 추적도 효과가 작음
- 공 검출 v4: TrackNet 방송 영상 추가 학습 → 처음 보는 방송 영상(game6~10)에서 종합 점수(F1) 0.42 → 0.75
- YOLO11n vs YOLO26n: 방송 영상 동급(0.75 / 0.74), 우리 영상 2개에서는 엇갈림 → 우열 결론 없음
- 선수 검출 6종 비교: 적중률 모두 99%대. 11n·26n CPU 속도 재측정 결과 PyTorch 동급(62/61ms), ONNX Runtime에서 26n이 빠름(60.6 대 47.7ms) → 속도는 11n 선택의 근거가 아님. 서비스 지표(정답 선수 기준 이동거리·평균 속도)도 동급이라 **서비스 모델을 26n으로 교체**(6절)

- 오출력률 = 공 없는 프레임 중 출력 비율 (TrackNet은 공 없는 프레임이 3.7%뿐이라 신뢰 낮음)

## 2. 공 추적기 (`webapp/backend/ball_tracker.py`)

방식
- 프레임별 공 후보(x, y, conf)에 점수(conf 로짓 + 보정)를 주고 연결 비용(이동 속도, 건너뛴 프레임, 정지한 물체)을 뺀 합이 최대인 경로를 동적 계획법으로 탐색
- 구간 시작 비용으로 고립된 오검출 제거, 빈 프레임은 직선 보간
- 구간 끝 점수 조건(`trim_conf`), 구간 내 확실한 검출 조건(`min_peak_conf`) 옵션
- 단위 테스트 10개(`tests/test_ball_tracker.py`), 버그 주입 확인 완료

### 평가 1~3차 (v2 검출 기준, 설정은 조정용 데이터에서만 선택)

| 차수 | 변경 | 결과 요약 |
|---|---|---|
| 1차 | 속도·비용 파라미터 탐색 | 방송 영상 재현율 13.9% → 29.8%(F1 0.24 → 0.44), 우리 영상 정밀도 하락(video10 오출력률 9% → 71%) |
| 2차 | 구간 조건(`min_peak_conf`, `min_nodes`, `max_gap`) 추가 | 정밀도 소폭 회복(video9 50.7% → 53.0%), 핵심 문제 유지 |
| 3차 | 진단 반영: `conf_bias`, `trim_conf` 탐색 | 조정용에서 기준 방식과 동등(video9 F1 0.807 대 0.804), 시험용 이득 없음(game6-10 F1 0.289 대 0.291) |

오출력 원인 진단 (video9, 2차 설정)
- 정답 공 170프레임 전부 20px 이내 적중(오차 중앙값 3.2px, 최대 10.5px), 단 같은 구간에서 프레임별 최고 검출도 169/170 적중(쉬운 구간)
- 출력 321프레임 중 틀린 151프레임: 공이 사라진 뒤 낮은 점수 오검출(중앙값 0.36, 진짜 공 중앙값 0.48)이 이어져 구간이 늘어난 것
- 결론: 병목은 추적이 아니라 검출 모델의 방송 영상 재현율(10~14%)

## 3. 공 검출 v4 학습

조건: v2와 동일(`yolo11n.pt`에서 시작, epochs 50, imgsz 960, batch 16, patience 15), 데이터만 추가
같은 조건에서 모델 구조만 바꿔 비교

| 모델 | 종료 epoch (최고) | 소요 | 검증 mAP50 | 검증 정밀도 / 재현율 | 계산량 |
|---|---|---|---|---|---|
| v4 yolo11n | 42 (27) | 36분 | 0.671 | 0.683 / 0.687 | 6.4 GFLOPs |
| v4 yolo26n | 45 (30) | 50분 | 0.737 | 0.819 / 0.694 | 5.3 GFLOPs |

- 검증 데이터가 v2와 달라(v4는 TrackNet game5 추가) v2의 mAP50(0.686)과 직접 비교 불가
- 크기 s 학습(11s, 26s)은 우열이 가려지지 않아 미수행

## 4. 모델 비교 (공 검출, 공평한 비교)

설정: 모델마다 확신도 기준·추적 설정을 조정용(video9 + TrackNet game5)에서만 선택(추적 설정 후보 18개, 확신도 기준 후보 17개), 선택한 설정으로 시험 평가

### 처음 보는 방송 영상 (TrackNet game6~10, 시험)

| 모델 | 방식 | 재현율 | 정밀도 | F1 |
|---|---|---|---|---|
| v2 | 공 추적 | 27.5% | 87.3% | 0.418 |
| v4 yolo11n | 프레임별 검출 | 42.3% | 52.5% | 0.468 |
| v4 yolo11n | 공 추적 | 67.1% | 85.4% | **0.752** |
| v4 yolo26n | 프레임별 검출 | 43.9% | 62.3% | 0.515 |
| v4 yolo26n | 공 추적 | 68.9% | 78.9% | **0.736** |

### 우리 영상 (참고)

| 영상 | v2 (추적) | v4 yolo11n (추적) | v4 yolo26n (추적) |
|---|---|---|---|
| video9 F1 (조정에 사용) | 0.692 | 0.588 | 0.835 |
| video10 F1 (참고) | 0.440 | 0.762 | 0.000 |

해석
- v4 학습(방송 영상 추가)으로 처음 보는 방송 영상 성능 대폭 향상, 이때 추적이 재현율을 크게 높임(11n: 프레임별 47% → 추적 67%)
- yolo11n vs yolo26n: 방송 영상 동급, 우리 영상은 반대 경향(11n은 video9 오검출 증가, 26n은 video10에서 조정된 설정이 너무 엄격해 공을 전혀 못 찾음)
- 우리 영상 시험 데이터가 공 170프레임(video9)·64프레임(video10)뿐이라 우열 결론 불가

## 5. 선수 검출 모델 비교 (사전학습 모델 그대로, 학습 없음)

조건: conf 0.3, imgsz 960, 정답 선수 위치가 검출 박스(10% 여유) 안에 들어오는지로 적중 판정

| 모델 | 크기 | 적중률 video9 / video10 | 추가 검출(관중 등, 프레임당) | GPU | CPU (PyTorch) |
|---|---|---|---|---|---|
| yolo11n | 5.6MB | 99.5% / 100% | 4.9 / 2.1 | 28ms | **85ms** |
| yolo11s | 19.3MB | 99.6% / 99.8% | 8.0 / 2.0 | 23ms | 123ms |
| yolo11m | 40.7MB | 99.6% / 99.6% | 6.1 / 2.0 | 33ms | 433ms |
| yolov8n | 6.6MB | 98.9% / 100% | 3.4 / 2.2 | 22ms | 120ms |
| yolo26n | 5.5MB | 99.6% / 100% | 4.4 / 2.2 | 38ms | 289ms |
| yolo26s | 20.4MB | 99.6% / 100% | 7.2 / 2.1 | 28ms | 1,011ms |

- 선수 적중률은 모든 모델이 99%대로 차이 없음(쉬운 문제)
- 표의 CPU(PyTorch) 열은 PC가 바쁠 때 1회 측정한 값이라 신뢰할 수 없음(재측정한 11n 62ms·26n 61ms와 크게 다름). 11n·26n의 확정 속도는 6절 재측정 표 참조, 나머지 모델은 재측정 안 함

### 실행 환경별 CPU 속도 재측정 (11n vs 26n)

조건: CPU(Xeon W-2223) FP32, 입력 544x960, video9 40프레임(워밍업 5), 3회 반복 중 최소 중앙값, 모델을 ONNX·OpenVINO로 변환해 측정

| 모델 | PyTorch | ONNX Runtime | OpenVINO |
|---|---|---|---|
| yolo11n | 62.1ms | 60.6ms | 69.8ms |
| yolo26n | 61.0ms | **47.7ms** | 66.2ms |

- 회차별 값: 11n 67/62/86, 64/61/61, 87/70/81 · 26n 62/63/61, 48/48/48, 142/86/66 (PyTorch, ONNX, OpenVINO 순)
- PyTorch: 동급. 이전 측정(11n 85ms, 26n 289ms)은 PC가 바쁠 때 잰 값으로 폐기
- ONNX Runtime: 26n이 약 21% 빠름(Ultralytics 문서의 보고와 같은 방향)
- OpenVINO: 26n 회차 값이 흔들려(142→66) 우열 판단 불가
- 한계: PC 1대, 40프레임, 측정 중 원인 불명의 배경 부하(시스템 CPU 30~90%, 프로세스별 합은 낮음), 회차별 CPU 사용률은 `results/runtime_comparison_log.txt`에 기록

### 서비스 파이프라인 기준 비교 (11n vs 26n, 정답 선수 기준)

조건: video9 전체 627프레임, 같은 코트 보정(눈대중 근사 4점), conf 0.3, imgsz 960, BoT-SORT 기본, GPU
선수 번호는 정답 위치(`video9_player.csv`)와 겹치는 박스의 최다 track id로 지정(정답 좌/우는 선수 2명이 아니라 한 선수의 좌·우 발 위치)

| 항목 | yolo11n | yolo26n |
|---|---|---|
| 총 이동거리 | 28.39m | 28.65m |
| 평균 속도 | 2.77m/s | 2.79m/s |
| 최고 속도 | 10.28m/s | 9.51m/s |
| 처리 속도 | 67.6ms/프레임 | 58.1ms/프레임 |

- 추적 안정성(정답 위치 기준, video9·video10 좌우 4건): 두 모델 모두 선수를 번호 하나로 끊김 없이 추적(id 바뀐 횟수 0, 커버리지 99~100%) → `results/tracking_stability_log.txt`
- 이동거리·평균 속도는 1% 이내 동일, 최고 속도는 순간값이라 차이 큼(7%)
- 한계: 영상 1개, 눈대중 코트 보정(상대 비교만 의미), 실제 이동거리 정답 없음

정정 기록
- 같은 날 처음 실행한 비교(11n 33.83m / 26n 0.17m)는 방법 결함이었음: 자동 선수 선택("첫 프레임에서 코트 근처 가장 큰 박스")이 video9 첫 프레임에 선수가 없어 멀리 서 있는 다른 사람(id 2)을 선택. 모델 성능 차이가 아님
- 이전 INT8 전후 비교(`int8_service_compare_log.txt`의 33.83m→33.99m)도 같은 자동 선택을 사용 → 그 값은 선수가 아닌 사람 기준. FP32 대비 INT8의 상대 변화(+0.5%)만 참고 가능, 실제 선수 기준 재측정은 미실시
- 서비스는 사용자가 고른 프레임 시각에 코트 안 가장 큰 박스를 player1로 자동 선택(클릭은 player2 추가용)하므로, 그 시각에 선수가 없으면 같은 오선택이 서비스에서도 생길 수 있음(미보완)

결정: 서비스 모델을 yolo26n으로 교체(2026-11)

## 6. 서비스 모델 선택(YOLO11n → YOLO26n)과 한계

- 서비스의 시작 모델이 YOLO11n이었던 이유는 기록 없음(초기 선택은 비교 없이 진행)
- 이후 크기(n/s/m)·버전(v8/11/26) 비교 수행
- 결과: 선수 적중률 동급, 서비스 지표(이동거리·평균 속도) 동급, 추적 안정성 동급, 속도는 CPU PyTorch 동급·ONNX Runtime에서 26n 우세·GPU 26n 우세(58 대 68ms/프레임)
- 결정: 정확도 손해 없이 속도가 같거나 빠르고 더 최신 모델이라 26n으로 교체. **26n이 더 정확하다는 근거는 없음**(우열 없음, 속도·최신성이 이유)
- 11n에 묶여 있던 것: INT8/OpenVINO 경량화 실험(`int8_experiment.md`)은 11n 기준이라 26n으로는 미수행, 서비스는 INT8을 쓰지 않으므로 영향 없음
- 한계: 위 재측정·서비스 지표 비교의 한계 참조(영상 1개, 근사 코트 보정, 측정 중 원인 불명의 배경 부하), 공 검출 비교에서도 우열 없음(4절)

## 7. 한계

- 공 검출·추적은 서비스에 연결하지 않은 오프라인 실험
- 우리 영상 시험 데이터 2개(공 보이는 프레임 170, 64)로 모델 우열 판단 불가
- TrackNet 검증·조정 데이터와 시험 데이터는 같은 경기 데이터라 도메인이 같음(우리 영상과는 다름)
- 모델별 설정 선택은 격자 탐색 18개, 모델 26n의 video10 실패는 설정 선택의 취약성
- 학습 1회, 조기 종료로 epoch 수 상이
